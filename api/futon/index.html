    FUTON, bases and combiners¶

    The FUTON concept page derives the model; this page is the reference for inro.models.futon: FUTON and its encoding, FUTONEncoding, the bases and combiners, and the SharedRows and Taps features its bases return on grids and for local bases.

    futon ¶

    FUTON: a fixed basis per axis, a tensor-network combiner and a head.

    FUTON computes output_activation(head(combiner(basis(x)))) for coordinates (N, C) in [-1, 1]:

    1. A basis gives each axis c features (N, K_c). Every basis takes in_features, the number of axes C; num_components, the widths K_c, one for all axes or one per axis; normalize, whether to L2-normalize each feature vector (default True); and grid_size, the sizes of the grid linspace(-1, 1, size) all inputs lie on, if any, whose features it tabulates once.
    2. A combiner fuses the axes with a tensor network, stated once as an einsum equation over the axes' projections, into (N, R) features.
    3. A head maps them to the signal: "linear", "mlp" or "identity".

    Points share the features of their shared coordinates. On a grid, a basis gives each axis as SharedRows, a table of its coordinates and every point's row in it, so a combiner projects S_c rows rather than N points, and it returns its features as a GridFeatures, its equation and operands, which the head's first linear layer reads off the whole grid in one einsum with its weight when the batch covers the grid. A kernel of compact support gives scattered points only their nonzero features, as Taps. Coordinates that need gradients are evaluated point by point.

    SharedRows ¶

    Features of one axis on a grid: a table of S rows and each point's row.

    Behaves as the (N, K_c) matrix table[rows], which dense returns. A product with a factor projects the S rows rather than N points, and the product shares the rows still.

    Attributes:

    • table (Tensor) –

      Features (S, K_c) of the axis's S coordinates.

    • rows (Tensor) –

      Row of each of the N points.

    Taps ¶

    Sparse features of one axis: the L nonzero values of each coordinate.

    Behaves as the (N, K_c) matrix whose row n holds values[n] in columns start[n] to start[n] + L - 1.

    Attributes:

    • values (Tensor) –

      Nonzero features (N, L).

    • start (Tensor) –

      First column (N,) of each row's window.

    • compiled (bool) –

      Whether a compiled graph made the taps, whose product then gathers windows of rows. Set where the taps are made: a product traced after a graph break may no longer see torch.compiler.is_compiling().

    TriangleBasis ¶

    TriangleBasis(in_features: int, num_components: Sizes, normalize: bool = True, grid_size: Sizes | None = None)

    Triangles (hats) \(\max(0, 1 - |x - \mu_k| / w)\) centered on \(\mu_k = -1 + k w\), spaced by \(w = 2 / (K_c - 1)\): piecewise-linear interpolation, two components nonzero, K_c >= 2.

    LanczosBasis ¶

    LanczosBasis(in_features: int, num_components: Sizes, radius: int = 3, normalize: bool = True, grid_size: Sizes | None = None)

    Lanczos kernels, windowed sines centered on \(\mu_k = -1 + k w\), spaced by \(w = 2 / (K_c - 1)\), K_c >= 2 * radius.

    With offset \(t = (x - \mu_k) / w\) and radius \(a\), the kernel is \(\operatorname{sinc}(t) \operatorname{sinc}(t / a)\) for \(|t| < a\) and zero elsewhere: one at its own center, zero at the others, and at most 2 * a components nonzero.

    GridFeatures ¶

    GridFeatures(equation: str, operands: list[Operand], shape: tuple[int, ...])

    A combiner's features on a grid, its network not yet contracted.

    torch.nn.functional.linear, as a head's first layer calls it, contracts the network with the layer's weight in one einsum over the axes' tables when the grid has at most 64 / out_features cells per point, which spares every point's features and the scatter of their gradients. A sparser batch, and every other torch function, take the features point by point, dense.

    CPCombiner ¶

    CPCombiner(in_features: Sequence[int], rank: int)

    TRCombiner ¶

    TRCombiner(in_features: Sequence[int], rank: int)

    Tensor-ring (TR) combiner.

    Axis c contracts its features with a core (R, K_c, R) into an R x R matrix, and the matrices multiply in order, ...ab,...bc->...ac on two axes. The product is flattened, R**2 wide, leaving the closure of the ring, such as a trace, to what follows. Extends the paper's CP model.

    Parameters:

    • in_features (Sequence[int]) –

      Number of features K_c of each axis.

    • rank (int) –

      Tensor-ring rank R.

    References

    Zhao et al., "Tensor Ring Decomposition", arXiv 2016.

    TuckerCombiner ¶

    TuckerCombiner(in_features: Sequence[int], rank: Sizes)

    Tucker combiner.

    Projects axis c to rank[c] channels with its factor (K_c, rank[c]) and contracts the projections with a core (rank[0], ..., rank[C - 1], max(rank)), such as ...b,abz,...a->...z on two axes whose second rank is the larger. With a linear head the weight tensor is in Tucker format, and CP is the case of a superdiagonal core. Extends the paper's CP model.

    Parameters:

    • in_features (Sequence[int]) –

      Number of features K_c of each axis.

    • rank (Sizes) –

      Multilinear rank, shared or per axis; the network has as many channels as its largest.

    References

    Tucker, "Some mathematical notes on three-mode factor analysis", Psychometrika 1966.

    def __init__(self, in_features: Sequence[int], rank: Sizes):
    super().__init__(in_features)
    modes = len(self.in_features)
    self.rank = _broadcast(rank, modes, "rank")
    widths = zip(self.in_features, self.rank)
    self.factors = nn.ParameterList(torch.empty(k, r) for k, r in widths)
    self.core = nn.Parameter(torch.empty(*self.rank, max(self.rank)))
    # Per point, the core absorbs one projection at a time, largest rank first,
    # which keeps the intermediates small; z is the core's output.
    self.order = sorted(range(modes), key=self.rank.__getitem__, reverse=True)
    ranks = string.ascii_lowercase[:modes]
    first, *others = (f"...{ranks[c]}" for c in self.order)
    self.equation = ",".join([first, f"{ranks}z", *others]) + "->...z"
    self.reset_parameters()
    self.shape = (max(self.rank),)

    FUTON ¶

    FUTON(in_features: int, out_features: int, basis: ModuleSpec, combiner: ModuleSpec, head: ModuleSpec, output_activation: Activation | None = None)

    Fourier Tensor Network for implicit neural representations.

    Computes output_activation(head(combiner(basis(x)))). Each stage is a spec: a module instance, a registry key, a module class, or a (key_or_class, kwargs) pair. Registry keys:

    • Bases: "cosine", "sinc", "legendre", "chebyshev", "triangle", "lanczos".
    • Combiners: "cp", "tr", "tucker".
    • Heads: "linear", "mlp", "identity".

    Parameters:

    • in_features (int) –

      Number of coordinate axes C.

    • out_features (int) –

      Number of output channels D.

    • basis (ModuleSpec) –

      Basis spec; see FUTONEncoding.

    • combiner (ModuleSpec) –

      Combiner spec; see FUTONEncoding.

    • head (ModuleSpec) –

      Head spec, built as head(encoding.out_features, out_features, **kwargs).

    • output_activation (Activation | None, default: None ) –

      Callable applied to the output; None uses the identity.

    Shape
    • Input: (..., C) coordinates in [-1, 1].
    • Output: (..., D).

    Starts¶

    futon_inits ¶

    Starts of FUTON fitted to a signal, and the CP algebra its bounds and solvers share.

    On a grid, a CP FUTON, a CP combiner with a linear head, is a CP tensor: its factor of axis c is the axis's basis times the factor matrix, and its factor of the channels is the head's weight. A start sets these blocks of a built FUTON from the signal, in place, before training:

    • SVDInit gives the R components the R heaviest rank-one terms of the signal's low frequencies, found by nested SVDs;
    • ALSInit refines those terms by alternating least squares first.

    SVDInit dataclass ¶

    SVDInit(*, cut: int = 4, scale: float = 1.0)

    Start a FUTON from the heaviest rank-one terms of a signal's low frequencies.

    Called on a built FUTON and a signal (N_1, ..., N_C, D) on the grid linspace(-1, 1, N_c) of each axis, such as a coordinate dataset's target, it sets the model's parameters in place:

    1. Project the signal onto the lowest K_c // cut cosines of each axis c, normalized per point as in CosineBasis.
    2. Expand the projection, a tensor of the C axes and the channels, into orthonormal rank-one terms by nested SVDs: the first splits off the shortest mode, and each next one the shortest mode left, which leaves the most terms.
    3. Give the R heaviest terms, as refine returns them, to the R components: a term's vector of axis c, fitted to the model's basis on the grid, becomes a column of factor c, and its vector of the channels a column of the output factor, the head's weight.

    Each term's weight, times scale, is shared evenly by its component's factors and output column. Components beyond the terms keep their draw behind a zero output column, silent until trained, and a head bias starts at zero. The start runs on the model's device, in its precision, and raises a ValueError for a model that is not a CP FUTON.

    Parameters:

    • cut (int, default: 4 ) –

      Divisor of each axis's component count K_c that leaves the frequencies kept.

    • scale (float, default: 1.0 ) –

      Factor of the output before the activation. With tanh, 2 starts a signal of -1 and 1 near -0.96 and 0.96.

    Solvers¶

    A FUTON with a CP combiner and a linear head, both without bias, is multilinear: with the other blocks held, its output is linear in each factor matrix and in the head, so fitting one block is a least-squares problem. inro.LeastSquares and inro.MultiplicativeUpdate sweep the blocks once per batch, and inro.train takes them in place of Adam, on the same datasets:

    model = inro.FUTON(
    2, 3,
    basis=("cosine", {"num_components": [H // 2, W // 2], "grid_size": (H, W)}),
    combiner=("cp", {"rank": 280}),
    head=("linear", {"bias": False}),
)
solver = inro.LeastSquares(model, momentum=0)
result = inro.train(model, dataset, dataset, optimizer=solver, num_steps=500, metrics={"psnr": inro.psnr})

    On a grid with \(M_c\) coordinates along axis \(c\), the model is a CP tensor with one factor per axis, the response \(\boldsymbol{T}_c \boldsymbol{U}^{(c)}\) of the basis's table \(\boldsymbol{T}_c \in \mathbb{R}^{M_c \times K_c}\), and one for the channels, the head \(\boldsymbol{V}\). With the other blocks held, the normal equations of the mean squared error for \(\boldsymbol{U}^{(c)}\) are small, the size of the block itself:

    \[ \boldsymbol{P}_c \boldsymbol{U}^{(c)} \boldsymbol{Q}_c = \boldsymbol{B}_c , \qquad \boldsymbol{P}_c = \tfrac{1}{M_c} \boldsymbol{T}_c^\top \boldsymbol{T}_c , \qquad \boldsymbol{Q}_c = \boldsymbol{V}^\top \boldsymbol{V} \odot \bigodot_{j \ne c} \tfrac{1}{M_j} \big(\boldsymbol{T}_j \boldsymbol{U}^{(j)}\big)^\top \big(\boldsymbol{T}_j \boldsymbol{U}^{(j)}\big) , \]

    where \(\boldsymbol{P}_c\) is the basis's Gram matrix and \(\boldsymbol{B}_c\) the targets' correlation with the rest of the model. The head's are \(\boldsymbol{V} \boldsymbol{G} = \boldsymbol{C}\), with \(\boldsymbol{G}\) the elementwise product of every axis's Gram matrix and \(\boldsymbol{C}\) the targets' correlation with the whole CP product.

    Alternating least squares: every block takes its problem's solution, one side at a time, each with a ridge against collinear functions or components.

    • From the left, by the inverse of \(\boldsymbol{P}_c\), which depends on the basis and the grid alone and is made once on a declared grid; from the right, by the Cholesky factorization of \(\boldsymbol{Q}_c\).
    • Any basis will do, signed or not, and the parameters start from normal draws.
    • With an activation at the output the targets are Gauss-Newton ones, refitted every sweep, so the sweeps descend the activated model's error rather than minimize a fixed one.

    Lee and Seung's updates, for a nonnegative model. With everything nonnegative, the two parts of a block's gradient are too, and the update multiplies the block elementwise by their ratio:

    \[ \boldsymbol{U}^{(c)} \leftarrow \boldsymbol{U}^{(c)} \odot \boldsymbol{B}_c \oslash \big(\boldsymbol{P}_c \boldsymbol{U}^{(c)} \boldsymbol{Q}_c\big). \]
    • That is the minimizer of the auxiliary function Lee and Seung build for a quadratic with a nonnegative Hessian: the block's problem is never worse after the update, the block stays nonnegative, and one at a fixed point stays there. An entry is set to zero where a minibatch's estimate of \(\boldsymbol{B}_c\) is negative.
    • A block's problem is fixed for the sweep and an update costs two small products, so each block takes inner of them in a row, as Gillis and Glineur propose.
    • The model needs a nonnegative basis, the triangle with normalize=False so that its functions sum to one, nonnegative targets and nonnegative parameters. A signal in \([-1, 1]\) is fitted through the affine output activation lambda z: 2 * z - 1.

    A few facts hold for both:

    • Batches. A batch is taken as points of the grid the basis declares, or else of the grid of its distinct coordinates. The Gram matrices are the grid's, and a right-hand side is what the model explains on the grid plus what it misses at the batch's points, \(\boldsymbol{B}_c = \boldsymbol{P}_c \boldsymbol{U}^{(c)} \boldsymbol{Q}_c + \boldsymbol{T}_c^\top \boldsymbol{E}_c / N\) for the residual's correlation \(\boldsymbol{E}_c\) over the \(N\) points. That is exact on a whole grid and, on a random share of it, the whole grid's in expectation, with the noise of the residual rather than of the signal. A sweep thus costs a few products of matrices over the grid whatever share of it the batch holds.
    • Monotony. On a whole grid at lr=1, no update of MultiplicativeUpdate, or of LeastSquares without its ridge, raises the batch's error.
    • Scales. Every axis's response is held at unit mean square, the head's columns taking the scales, which fixes the freedom of a CP model to trade scale between its blocks.
    • Momentum. momentum averages each block's statistics over the batches, as online matrix factorization does (Mairal et al., 2010), with weights that sum to one from the first batch on. The newest batch's weight is the solver's lr: it starts at 1 - momentum, and inro.train anneals it to a hundredth. Without momentum it stays one, and every sweep solves the batch's own problem.

    The notebook notebooks/futon_solvers.ipynb compares these solvers with Adam, and the error bound page uses LeastSquares on the whole grid.

    futon_solvers ¶

    Block coordinate descent for FUTON: solvers in place of a gradient optimizer.

    A FUTON with a CP combiner and a linear head, both without bias, is multilinear, so fitting one block with the others held is a least-squares problem. BCD sweeps the blocks once per batch and leaves each block's update to a subclass: LeastSquares solves the block's problem, for any basis, and MultiplicativeUpdate takes Lee and Seung's step, which keeps a nonnegative model nonnegative. inro.train takes both in place of Adam, on the same datasets.

    BCD ¶

    BCD(model: FUTON, momentum: float = 0.9, initialize: bool = True, **defaults: Any)

    Block coordinate descent over a FUTON's factor matrices and head.

    On a grid the model is a CP tensor, so with the other blocks held each block has small normal equations, which a subclass's solve handles. step updates the factors in order, then the head, and holds every axis's response at unit mean square, the head's columns taking the scales.

    A batch is taken as points of the grid the basis declares, or else of the grid of its distinct coordinates. Only the residual comes from its points, so a sweep costs about the same on any share of the grid, and a whole grid with momentum=0 is the fast setting.     MultiplicativeUpdate ¶

    MultiplicativeUpdate(model: FUTON, inner: int = 16, floor: float = 1e-12, momentum: float = 0.9, initialize: bool = True)

    Lee and Seung's multiplicative updates, for a nonnegative model.

    The update multiplies a block elementwise by the ratio of its gradient's two parts, value * right / (left @ value @ gram). It never worsens the block's problem and keeps the block nonnegative; each block takes inner of them in a row, as Gillis and Glineur propose.

    def solve(
    self, value: Tensor, right: Tensor, gram: Tensor, left: Tensor | None = None

    """Return the block after ``inner`` updates; see :meth:`BCD.solve`."""
    floor = self.defaults["floor"]

        # zero and keeps its value; one whose right-hand side is negative,

        # constrained minimizer of its auxiliary function.
        ratio = (right / denominator.clamp_min(floor)).clamp_min(0)
        value = value * torch.where(denominator > floor, ratio, 1.0)
    return value

    futon_bounds ¶

    Bounds on how well a FUTON with a linear head can fit a sampled signal.

    On a signal's sampling grid, the error of a FUTON with a CP combiner and a linear head, both without bias, splits exactly in two: the error of the best approximation in the basis's span, which no rank removes, and the CP misfit of the signal's coefficients in an orthonormal basis of that span. futon_bound computes the first exactly, brackets the best second, and returns the factors of a FUTON that attains the upper bound.     @torch.no_grad()
def futon_bound(
    signal: Tensor,
    features: Sequence[Tensor],
    ranks: int | Sequence[int],
    sweeps: int = 0,
    tol: float = 3e-5,
) -> FUTONBound:
    """Bound the best grid error of a FUTON with a linear head on a signal.

    Every FUTON with a CP combiner and a linear head, both without bias, with these
    per-axis features and rank ``R`` has a mean squared error on the grid of at least
    the bound's ``lower`` at ``R``, and the one given by its ``factors`` has exactly its
    ``upper``; no FUTON goes below ``truncation``. The bounds depend on the basis only
    through each axis's span.

    Args:
        signal: Samples ``(N_1, ..., N_C, D)`` on a grid.
        features: Per axis ``c``, the basis ``(N_c, K_c)`` at that axis's grid
            coordinates, orthonormal or not. For a FUTON's basis on a coordinate
            dataset's grid, it is
            ``basis.axis_features(torch.linspace(-1, 1, N_c), c)``.
        ranks: CP ranks ``R`` to bound.
        sweeps: Maximum number of alternating least-squares sweeps that refine each
            upper bound, in float32, from its SVD form, the ``R`` heaviest terms of the
            nested SVDs. The default, ``0``, returns the SVD form; a sweep never
            raises the bound.
        tol: Fraction of the bound below which a sweep's decrease stops the sweeps,
            when there are any.

    Returns:
        The bounds and the factors that attain the upper ones, on the CPU.

    Raises:
        ValueError: If ``features`` is not one matrix of ``N_c`` rows per axis.

    Examples:
        >>> from inro import SincBasis
        >>> signal = torch.rand(32, 32, 3) * 2 - 1
        >>> basis = SincBasis(2, num_components=16)
        >>> grid = torch.linspace(-1, 1, 32)
        >>> features = [basis.axis_features(grid, c) for c in range(2)]
        >>> bound = futon_bound(signal, features, ranks=[4, 8])
        >>> psnr = 10 * torch.log10(4 / bound.upper)  # guaranteed, in dB
        >>> psnr.shape
        torch.Size([2])
    """
    ranks = sorted({ranks} if isinstance(ranks, int) else set(ranks))
    signal = signal.double()
    *sizes, channels = signal.shape
    if len(features) != len(sizes) or any(
        len(phi) != size for phi, size in zip(features, sizes)
    ):
        raise ValueError(
            f"expected one feature matrix of N_c rows per axis of {tuple(sizes)}"
        )

    # Phi_c / sqrt(N_c) = Q_c B_c with Q_c an orthonormal basis of its span;
    # directions the grid cannot tell from zero are left out. The small
    # decompositions here and below run on the CPU, where they are fastest.
    bases, inverses = [], []
    for phi in features:
        phi = phi.double().cpu() / math.sqrt(len(phi))
        q, s, vh = torch.linalg.svd(phi, full_matrices=False)
        keep = s > s[0] * max(phi.shape) * torch.finfo(s.dtype).eps
        bases.append(q[:, keep].to(signal))
        inverses.append(vh[keep].T / s[keep])  # B_c^+, (K_c, K_c')

    # The signal's coefficients in the orthonormal basis of the span.
    coefficients = _project(signal, bases) / math.sqrt(math.prod(sizes))
    energy = float(coefficients.square().sum())
    truncation = max(float(signal.square().mean()) * channels - energy, 0.0)
    small = coefficients.cpu()
    lower = _tails(small, ranks)

    # The upper bounds' SVD form: per rank, the R heaviest terms of the nested SVDs
    # along the mode order that keeps the most energy in them. Modes of size one are
    # peeled first, at no cost, and the last two of an order share one SVD.
    single = [mode for mode in range(small.ndim) if small.shape[mode] == 1]
    rest = [mode for mode in range(small.ndim) if small.shape[mode] > 1]
    orders = [
        single + list(order)
        for order in permutations(rest)
        if len(order) < 2 or order[-2] < order[-1]
    ]
    expansions = []
    for order in orders:
        weights, vectors = _expansion(small, order)
        weights, index = weights.sort(descending=True)
        expansions.append((weights, [vector[index] for vector in vectors]))

    # The search runs in float32 on the signal's device; each bound is the
    # exact float64 error of the factors it finds.
    working = coefficients.float()
    upper, factors = [], []
    for rank in ranks:
        kept = [float(weights[:rank].square().sum()) for weights, _ in expansions]
        weights, vectors = expansions[kept.index(max(kept))]
        start = [vector[:rank].T.to(working) for vector in vectors]
        start[0] = start[0] * weights[:rank].to(working)
        chosen = [f.double() for f in _als(working, start, sweeps, tol, truncation)]
        residual = _residual(coefficients, chosen)
        # A rank's FUTON is one of every larger rank, with zero components added.
        if upper and upper[-1] < residual:
            residual, chosen = upper[-1], factors[-1]
        upper.append(residual)
        factors.append([F.pad(f, (0, rank - f.shape[1])) for f in chosen])

    # Back to the basis: U^(c) = B_c^+ U~^(c), with the head unchanged.
    mapped = [
        ([inverse @ f.cpu() for inverse, f in zip(inverses, chosen)], chosen[-1].cpu())
        for chosen in factors
    ]
    to_mse = 1 / channels
    return FUTONBound(
        ranks=ranks,
        truncation=truncation * to_mse,
        lower=(truncation + lower) * to_mse,
        upper=(truncation + torch.tensor(upper, dtype=torch.float64)) * to_mse,
        factors=mapped,
    )
